# SQLite is accessed through sqlx, with runtime-checked queries

Gantry reaches its SQLite database ([ADR-0004](0004-sqlite-is-the-source-of-truth.md)) through `sqlx`, with migrations embedded in the binary and run at startup. Queries use the runtime-checked API (`sqlx::query` / `query_as`), not the `query!` macros, so building Gantry never needs a live database or committed offline query metadata. We chose `sqlx` over `rusqlite` because Gantry is async throughout (tokio, one task per Printer). `rusqlite` would push every query through `spawn_blocking`, and we would have to write our own migration runner. The cost is that SQL mistakes surface in tests rather than at compile time, so every query needs a test against a real migrated database. Switching later would mean rewriting every query, which is why this is recorded.
